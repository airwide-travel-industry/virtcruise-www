## Purpose

Use these printable checklists to prepare, review, publish, and retire catalogue content consistently. A tick confirms that the check was completed against the current draft and approved source material.

**Package/business code:** ____________________  **Version:** ____________________  **Editor:** ____________________

## 1. New Package Checklist

- [ ] Business code is approved, unique, and suitable as a permanent identity.
- [ ] Canonical slug is lowercase, uses words separated by hyphens, and is unique.
- [ ] Package type is one of the accepted types.
- [ ] Car Rental is classified as `TRIP_ADD_ON`, not a primary package.
- [ ] Editorial owner is assigned.
- [ ] Title, summary, description, destination, and duration are complete.
- [ ] Featured status is intentional and approved.
- [ ] Inclusions, exclusions, itinerary, terms, FAQs, highlights, SEO, and call to action are prepared where applicable.
- [ ] At least one effective display price or approved **Price on request** entry is prepared.
- [ ] At least one validated, clean, public media item is prepared.
- [ ] No HTML markup, credentials, personal data, supplier-confidential detail, or unsupported promise is included.
- [ ] Customer wording follows DOC-001 and DOC-002 terminology.

## 2. Publishing Checklist

- [ ] Correct immutable version is under review.
- [ ] Editor and independent approver are different people.
- [ ] Title, summary, description, destination, duration, type, and featured status are correct.
- [ ] Highlights, inclusions, exclusions, itinerary, terms, FAQs, and call to action are complete.
- [ ] Pricing is effective at the intended publication time and has clear currency, amount/price-on-request, basis, and qualifier.
- [ ] Media is validated, clean, public, rights-cleared, ordered, and accessible.
- [ ] SEO fields supported by the accepted contract are complete and consistent.
- [ ] Preview matches the intended customer-safe publication.
- [ ] Current published version was compared with the proposed version.
- [ ] Historic quotes and bookings do not require change; publication must not rewrite them.
- [ ] Immediate or scheduled publication choice is approved.
- [ ] Scheduled time is unambiguous, shows time zone and offset, and is in the future.
- [ ] Optional withdrawal/retirement timing is approved where supported.
- [ ] Publication reason is factual and sufficient for audit.
- [ ] Public package, featured membership, destination/type filtering, slug, price, and media are checked after publication.

## 3. Image Checklist

- [ ] Image belongs to the current package version.
- [ ] Source and usage rights are recorded.
- [ ] Image contains no personal, confidential, unsafe, or misleading content.
- [ ] File type and file size meet the approved media policy.
- [ ] Approved dimensions/aspect ratio are used; no numeric recommendation is approved in the current architecture.
- [ ] Image is optimised before managed upload without visible quality loss.
- [ ] Cover/gallery role and display order are intentional.
- [ ] Alternative text communicates the image's relevant purpose.
- [ ] Caption adds useful context where applicable and does not repeat alt text mechanically.
- [ ] Validation status is clean and media is not marked private for public publication.
- [ ] Mobile crop/readability and desktop quality were reviewed in planned preview.
- [ ] Image is not upscaled from a low-resolution source.

## 4. SEO Checklist

- [ ] SEO title is accurate, distinctive, and consistent with the package title.
- [ ] SEO description summarises the customer value without unsupported claims.
- [ ] Canonical slug/URL intent is correct.
- [ ] Open Graph title, description, and image are prepared only if supported by the accepted SEO schema.
- [ ] Featured image is rights-cleared and suitable for sharing where supported.
- [ ] Keywords are used only if an accepted schema explicitly supports them.
- [ ] No keyword stuffing, duplicate title, misleading price, or unavailable destination claim.
- [ ] Canonical URL does not conflict with a previous slug or alias policy.
- [ ] Planned preview and public projection were checked where available.

## 5. Retirement Checklist

- [ ] Correct currently published package/version is identified.
- [ ] Retirement reason and business approval are recorded.
- [ ] Customer, quote, booking, campaign, and link impact is assessed.
- [ ] Existing quotes and bookings remain unchanged.
- [ ] Replacement content or redirect/alias expectation is documented where policy requires it.
- [ ] Featured and campaign references are reviewed.
- [ ] Retirement timing and customer communication are approved.
- [ ] Package is removed from public discoverability after the accepted transition.
- [ ] Audit evidence and retained versions remain available.
- [ ] No package with publication history is deleted.
