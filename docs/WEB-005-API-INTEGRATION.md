# WEB-005 Public API Integration

## Public routes

| Purpose | Method and path | Authentication |
| --- | --- | --- |
| Catalogue | `GET /api/v1/catalogue/packages` | Public |
| Featured | `GET /api/v1/catalogue/packages/featured` | Public |
| Detail | `GET /api/v1/catalogue/packages/{slug}` | Public |

The public client never calls `/api/v1/content/**`, draft, review, audit, or Content Studio routes.

## Mapping

`title`, `summary`, `description`, `destination`, `durationDays`, `featured`, `highlights`, `seo`, `callToAction`, `pricing`, `media`, and `publishedAt` are mapped from the published projection. Pricing supports multiple entries and price-on-request. Media is sorted by `order`; COVER/HERO is preferred for the cover, GALLERY is used for galleries, and references resembling managed/private/storage paths are discarded.

Optional SEO values safely fall back to the published title, summary, canonical package URL, cover and alt text. Detail rendering updates title, description, canonical, Open Graph and `TouristTrip` JSON-LD.

## Requests, validation and caching

The list adapter emits `page`, `size`, `search`, `destination`, `type`, and `featured` only when applicable. It accepts either the current array response or a page object with `content`, `number`, `size`, `totalElements`, and `totalPages`. Required identity, slug, title and destination fields are validated. Invalid JSON and incomplete objects fail closed.

GETs retry transient network/5xx failures. Responses retain normal browser cache semantics; an ETag is stored in memory and sent as `If-None-Match`. Publication is authoritative on the next request or revalidation. Offline storage contains only normalized responses previously received from the published endpoints.

## Backend gaps observed at `f84f337`

- No server pagination or search parameters.
- No public inclusions, exclusions, itinerary, terms, FAQ, or trip-add-on relationship fields.
- Media DTO exposes no caption field in the current projection builder.
- No ETag is generated by the controller, although `Cache-Control: public, max-age=60` is present.

These gaps were not changed because Package Content Management backend changes are explicitly excluded.
